# Логика первого порядка и задача автоматической проверки текста

Учебная программа демонстрирует упрощённый конвейер автоматической проверки текста:

1. токенизация русского предложения;
2. распознавание ограниченных языковых шаблонов;
3. преобразование распознанного предложения в логические клаузы (КНФ);
4. проверка логического следования выбранным методом.

Пользователь вводит базу знаний по одному предложению. Пустая строка завершает ввод. Затем вводится простой положительный запрос и выбирается один из трёх методов доказательства.

Программа проверяет **следует ли запрос из введённой базы знаний**, а не является ли утверждение объективно истинным в реальном мире.

## Поддерживаемые логические операции

Парсер поддерживает следующие связки в рамках описанных ниже шаблонов:

**Конъюнкция**

Ввод:
```text
Иван является студентом и сдал экзамен.
```

Логическая форма:
\[
Student(Иван) \land Passed(Иван)
\]

**Дизъюнкция**

Ввод:
```text
Иван является студентом или сдал экзамен.
```

Логическая форма:
\[
Student(Иван) \lor Passed(Иван)
\]

**Отрицание**

Ввод:
```text
Иван не сдал экзамен.
```

Логическая форма:
\[
\neg Passed(Иван)
\]

**Импликация**

Ввод:
```text
Если Иван сдал экзамен, то Иван получает зачёт.
```

Логическая форма:
\[
Passed(Иван) \rightarrow Credit(Иван)
\]

Также поддерживается условие с конъюнкцией:

```text
Если Иван является студентом и сдал экзамен, то Иван получает зачёт.
```

Для условной конструкции поддерживается форма `Если A и B, то C`: заключение `C` должно быть одним простым утверждением. Внутри условия `или` не поддерживается.

## Поддерживаемые предметные конструкции

Встроенный словарь предметной области небольшой. Распознаются утверждения о студентах, сдаче экзамена и получении зачёта.

Примеры:

```text
Все студенты, сдавшие экзамен, получают зачёт.
Каждый студент, который сдал экзамен, получает зачёт.
Иван является студентом.
Иван студент.
Иван сдал экзамен.
Анна сдала экзамен.
Студенты сдали экзамен.  # используйте имя в единственном числе для конкретного факта
Иван получает зачёт.
Иван не сдал экзамен.
Иван является студентом и сдал экзамен.
Иван является студентом или сдал экзамен.
Если Иван сдал экзамен, то Иван получает зачёт.
```

Имена объектов (например, Иван, Анна, Пётр) могут выступать в роли констант. Для них не требуется заранее создавать отдельные правила, если предложение соответствует распознаваемому шаблону.

## Запрос

Запрос должен быть **одним простым положительным утверждением**, например:

```text
Иван получает зачёт?
```

Составные запросы с `и`, `или`, `не` и условные запросы пока не поддерживаются. Логические связки можно использовать в предложениях базы знаний.

## Методы доказательства

После ввода базы знаний и запроса пользователь выбирает:

1. **Метод резолюций.** К базе знаний добавляется отрицание запроса; алгоритм применяет унификацию и резолюцию, пытаясь получить пустую клаузу.
2. **Прямой логический вывод.** Применяются правила Хорна к известным положительным фактам, пока не будет получен запрос или пока не закончатся применимые правила.
3. **Метод аналитических таблиц.** Проверяется выполнимость базы знаний вместе с отрицанием запроса посредством разложения формул, ветвления и закрытия противоречивых ветвей.

### Совместимость методов с логическими связками

- **Резолюции** работают с клаузами, в том числе с дизъюнкциями и отрицательными литералами.
- **Аналитические таблицы** в этой учебной реализации также работают с клаузальной базой, содержащей отрицательные и дизъюнктивные литералы.
- **Прямой вывод** рассчитан на положительные факты и правила Хорна. Если в базе есть дизъюнкция или отрицательный факт, метод сообщит, что такой набор формул не поддерживается.

Поэтому для экспериментов с `или` и `не` выбирайте резолюции или аналитические таблицы.

## Сборка и запуск

Требуется CMake и компилятор с поддержкой C++17.

Из корневой папки проекта выполните:

```bash
cmake -S . -B build
cmake --build build
```

Запуск в Linux/macOS:

```bash
./build/russian_text_resolution
```

В Windows исполняемый файл находится в каталоге сборки; точный путь зависит от используемого генератора CMake (например, `build/Debug/russian_text_resolution.exe`).

Для метода резолюций программа дополнительно предлагает задать лимиты числа клауз и проверяемых пар; можно нажать Enter, чтобы оставить значения по умолчанию.

После выполнения выводятся:
- результат проверки;
- время работы в микросекундах и миллисекундах;
- счётчик работы алгоритма (проверенные пары, применения правил или обработанные узлы — в зависимости от метода).

Измерение времени начинается непосредственно перед запуском выбранного алгоритма. Ввод текста и его NLP-разбор в это время не входят.

## Ограничения реализации

Это учебный NLP-анализатор на основе токенизации, словаря и заранее заданных шаблонов, а не универсальная система понимания русского языка.

Новые словоформы и языковые конструкции добавляются в `src/nlp_parser.cpp`. При добавлении нового типа логической формулы может потребоваться изменить не только NLP-парсер, но и внутреннее представление формул или алгоритмы вывода.
